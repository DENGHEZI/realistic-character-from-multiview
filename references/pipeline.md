# 分阶段做法与实测参数

以下数值来自一次服装与双手生产案例。底模 77,264 顶点、119,976 三角形和 3 张 4096 px 贴图。精修后为 62,580 顶点、123,439 三角形、14 材质、50 根骨骼和 6 张内嵌贴图，身高 1.695 m。具体预算以当前项目为准。另见 [常服角色精修案例](casual-character-case.md)。

## 阶段 0 · 确认底模身份

同一项目常并存多份模型。按下列顺序确认，任一项不吻合就停下来问用户：

1. 用用户点名的预览图反查生成记录里的 GLB 路径。
2. 记录指纹：顶点数、三角形数、材质数、贴图名与尺寸。
3. 检查是否有骨架。图生 3D 常见骨架为空，权重全靠自己加。
4. 检查 UV 图集名与贴图槽：`texture_pbr_*`、`_normal`、`metallic-roughness` 这类命名说明底模带 PBR 图集，可复用颜色细节。

**不要**因为“文件更新”就换底模。换底模等于换造型，之前的比例与切口全部作废。

## 阶段 1 · 比例归一

```python
REFERENCE_HEIGHT = 1.650   # 参考角色身高（m）
MODEL_HEIGHT = 1.695       # 项目身高（m）
SCALE = MODEL_HEIGHT / REFERENCE_HEIGHT
```

顺序固定为两次变换：

1. 导入后取所有顶点世界坐标，用 `(max+min)/2` 求水平中心、`min(z)` 求落地，平移到原点。
2. 按 `REFERENCE_HEIGHT / 高度跨度` 归一，此时模型高 1.650。
3. 建模全程在 1.650 坐标系里量取骨点与切口，最后统一 `* SCALE` 缩放网格与骨骼。

把缩放放在最后一步的好处：所有手写坐标都是“参考身高下的米”，换项目身高只改一个常量。

**坑**：`obj.dimensions` 在 `mesh.update()` 后不一定立即刷新，读它之前先 `bpy.context.view_layer.update()`，否则断言会拿到旧包围盒。

## 阶段 2 · 材质语义分配

不要手工刷材质槽。按面中心采样原图集，用颜色与空间联合判定：

```python
positions, rgb = sample_source(mesh)      # 面中心 + 该面 UV 中心处的图集 RGB
value = rgb @ (0.2126, 0.7152, 0.0722)    # 亮度
mint  = (g > r*1.045) & (g > b*1.009) & (value > .08)
red   = (r > g*1.27)  & (r > b*1.20)  & (r > .14)
buff  = (r > g*1.14)  & (g > b*1.20)
pale  = (value > .27) & (r > g*.96) & (g < b*1.18)
```

再用高度与前后位置收窄：

- 腿/裙：`z < 0.73` 且未被裙判定吃掉的，归皮肤。
- 衬衫：`pale` 且 `|x| < 0.085`、`y < -0.024`、`0.961 < z < 1.459`。
- 袖口：`pale` 且 `|x| > 0.431`、`0.867 < z < 1.065`。
- 裙：`torso` 且 `hem < z < skirt_top`，并且满足外轮廓 `hypot(x/.191, (y+.002)/.135) > 0.78`。
- 头发：亮度低、非薄荷绿，分冠部、额发、后发、鬓角、发尾五段。
- 金属：`buff` 且落在胸徽高度带，排除裙与衬衫。

**关键经验**：底模图集里存在“画错位置”的像素。本次裙腰正面有一片领结红纹被烘进了裙面，靠颜色分类无法消除，只能把该区域显式并入裙材质，再用独立格纹贴图覆盖。

## 阶段 3 · UV 与微浮雕

底模 UV 是按原图集排的，改材质后需要第二套 UV：

- 外套：`u = (x + .52y)/.012`、`v = (z + .39y)/.012`，两轴都用世界坐标投影，斜纹尺度 12 mm 一格。
- 裙：`u = atan2(x, -y+.006)/tau + .5`、`v = (z-.680)/.285`，柱面展开避免格纹在正前方被拉宽。
- 头发：`u = atan2(x-.007, -(y-.010))/tau + .5`，`v = (z-1.090)/.560`。
- 跨接缝的面：若同一面 UV 的 u 跨度 > 0.5，把小于 0.5 的一侧 `+1.0`，否则贴图会在背后翻折。

浮雕只加在需要的地方：头发用 `0.8 mm` 与 `0.45 mm` 两组正弦叠加，权重按“邻接头发面的比例”与顶部渐隐控制；裙正面被压出的红纹脊用 `5.5 mm` 高斯把顶点推回裙内。

## 阶段 4 · 发丝几何

用 BVH 在已有头发表面取点，生成窄条带：

- 19 条发缕，绕头一周从 `1.18` 到 `5.11` 弧度分布。
- 每条 35 行，沿 `z` 下落 `0.284 + 0.048*sin(...)`。
- 每条 3 列，半宽 `0.22 + 1.35*fade` mm，中间列再抬 `1.05 mm`。
- 发缕必须朝外：四边形的绕序按射线方向校正，否则会被背面剔除。
- 颜色贴图用方向性纹理（沿发流方向变化），不用高光条；法线强度 `0.34`，各向异性 `0.61`，粗糙度 `0.53`。

**坑**：Blender 5.3 的 Principled BSDF 没有 `Anisotropic IOR Level` 输入，只有 `Anisotropic`。写错名字会直接抛 `KeyError`。

## 阶段 5 · 灯光与渲染

```python
scene.render.engine = 'BLENDER_EEVEE'
scene.eevee.taa_render_samples = 48
scene.view_settings.view_transform = 'AgX'
scene.view_settings.look = 'AgX - Medium High Contrast'
scene.view_settings.exposure = -0.40
```

四盏面光：主光 580 W 暖白、补光 235 W 冷白、轮廓光 280 W 暖白打后发、衣料侧光 145 W。相机用正交，`sensor_fit='VERTICAL'`，这样不同部位近景可以只改 `ortho_scale`，透视关系保持一致。

**先渲原版基线**：用同一场景、同一机位渲一遍未改材质和未改灯光的底模。没有基线，之后所有“变好了”都是主观判断。

## 阶段 6 · 导出与回读

```python
bpy.ops.export_scene.gltf(
    filepath=..., export_format='GLB',
    use_selection=True, export_apply=False,
    export_animations=False, export_yup=True)
```

- 只选网格与骨架，避免把灯光相机带进 GLB。
- 在已验证的 Blender 导出组合中，`Base Color` 前的 `Mix(MULTIPLY, factor=1)` 可将纯色乘数写入 `baseColorFactor`。核对实际 GLB 的材质 JSON、纹理指针和回读像素。材质发白时同时查镜面、绒面扩展（`KHR_materials_sheen`）与环境光。若绒面层在回读时掩盖主色，优先调整该材质在导出中的绒面值；保持粗糙度、切线法线和基础色的分工。
- 回读必须两种格式各开一次，且断言三角形数一致。Blender 顶点数会比 GLB 少，因为 GLB 按 UV/法线接缝拆分顶点，这是正常的；三角形数必须相同。
- 骨架的 `custom_shape` 辅助物体会被当成第二个网格。检查时按 `bone.custom_shape` 排除，否则会出现“多了一个 Icosphere”的假失败。

## 阶段 7 · 对照图

三张图就够验收：

1. 全身：四分之三、正面、侧面、背面四联。
2. 手部：原版 / 精修静止 / 精修弯曲三列，手背与掌心各一行。
3. 局部：脸与发际、背面发束、校服前片，原版与精修并排。

统一底色 `#F8FAF9`、圆角 11 px、发丝边框 `#DBE1DF`。中文用 `C:/Windows/Fonts/msyhbd.ttc` 与 `msyh.ttc`。生成后断言每张局部图的时间戳不早于模型文件，避免拿旧渲染冒充新结果。
